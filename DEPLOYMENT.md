# Deployment and Production Guide

## Application summary
- Framework: Flask 3.1 (Python)
- Database: SQLite (file-based, `placement.db` by default)
- File uploads: local `uploads/` directory
- Entry point: `app.py` (`create_app()` factory, module-level `app`)
- Tests: `pytest` (`tests/`), 59 passing after production changes

## Production changes implemented
- Removed hardcoded `debug=True`; debug now controlled by `FLASK_DEBUG=1`.
- Bind host/port now use `0.0.0.0` and `PORT` (platform compatible).
- `SECRET_KEY` is required in production (runtime error if weak/default).
- Session cookies are `HttpOnly`, `SameSite=Lax`, and `Secure` in production.
- Reverse-proxy headers honoured via `ProxyFix` in production.
- Added `/health` and `/healthz` endpoints (DB connectivity check).
- Added `500` error handler with logging; request/runtime errors logged to stdout.
- Added `Procfile`, `runtime.txt`, `requirements-prod.txt`, `render.yaml`.
- Added GitHub Actions workflow (`.github/workflows/ci.yml`) for tests.

## Environment variables
| Variable | Required | Description |
|---|---|---|
| `SECRET_KEY` | Yes (prod) | Long random string (>= 24 chars) |
| `FLASK_ENV` | Yes (prod) | `production` in production |
| `DATABASE` | No | SQLite path (default `placement.db`) |
| `UPLOAD_FOLDER` | No | Upload directory (default `uploads/`) |
| `FLASK_DEBUG` | No | `1` to enable debug (dev only) |
| `PORT` | No | Listen port (default `5000`) |

## Hosting platform selection
Selected: Render (free web service) via `render.yaml`, with Vercel option available in `../student-internship-placement-system-vercel/`.
Rationale: Flask + SQLite deploys without code rewrite; Render supports Python, environment variables, and health checks. Vercel is available but uses ephemeral `/tmp` storage.

## Deployment steps (Render)
1. Push the project to a GitHub repository (user approval required).
2. Render -> New -> Blueprint -> select repo (uses `render.yaml`).
3. Set/verify `SECRET_KEY` (auto-generated by blueprint) and `DATABASE`.
4. Deploy; verify `/health` returns 200.
5. Login with seeded admin or register first user (becomes admin).

## Vercel deployment (alternative)
See `../student-internship-placement-system-vercel/README.md`. Uses `api/index.py` + `vercel.json`. Set `SECRET_KEY` in dashboard. Data is ephemeral on `/tmp`.

## CI/CD
GitHub Actions (`.github/workflows/ci.yml`) runs tests on push/PR. Deployment job is intentionally disabled until platform secrets are configured.

## Health checks and monitoring
- Endpoint: `GET /health` (and `/healthz`) returns JSON `{status, database, environment}` with HTTP 200/503.
- Platform logs: stdout/stderr captured by Render/Vercel.
- Application logs: Python `logging` at INFO in production.

## Backup and recovery
- SQLite DB file (`placement.db` or `DATABASE` path) must be backed up regularly.
- Uploads directory (`uploads/`) must be backed up with the DB.
- On Render free tier, disk is ephemeral; use a managed database (e.g. Neon/Postgres) and object storage for production persistence.
- Recovery: restore DB file + uploads, restart service, run `app.init_db()` if schema missing (idempotent).

## Common deployment failures and solutions
- `SECRET_KEY` missing/weak in production: set a strong value.
- Port binding errors: ensure `PORT` env var is used (app reads it).
- SQLite read-only filesystem (Vercel): DB path must be under `/tmp`.
- Missing schema: service calls `init_db()` on startup for local; on Vercel cold start `_ensure_db` handles it.
- Uploads not persisting: expected on ephemeral filesystems; use object storage.

## Security recommendations
- Always set a strong `SECRET_KEY`; never commit `.env`.
- Keep `FLASK_ENV=production` in production (disables debug).
- Use HTTPS (platform provides) so `Secure` cookies work.
- Restrict admin accounts; review seeded credentials.
- Validate/sanitize uploads (already limited to safe extensions and size).
- Add dependency updates and vulnerability scanning in CI.

## Known limitations
- SQLite + local uploads are not durable on free/ephemeral hosting.
- No automated backup job included.
- No external monitoring/APM integrated (platform metrics only).
- Vercel data resets on redeploy/scale.
