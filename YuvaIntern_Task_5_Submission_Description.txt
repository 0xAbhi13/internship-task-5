YuvaIntern Internship Task 5 - Deployment and Production

This submission documents the production preparation and deployment readiness of the Student Internship and Placement Management System, a Flask and SQLite web application. The project supports student registration and login, profile and resume management, internship discovery, application tracking, administrator workflows, and CSV reporting. The application was reviewed for deployment blockers, and production configuration was separated from development using environment variables. The SECRET_KEY is now required in production and weak or default values cause startup to fail. Debug mode is controlled by FLASK_DEBUG and defaults to off. Session cookies use HttpOnly, SameSite, and Secure flags in production, and reverse-proxy headers are handled with ProxyFix. A health check endpoint at /health and /healthz verifies database connectivity and returns HTTP 200 or 503. Error handlers for 400, 403, 404, and 500 were retained and extended with logging to stdout. Repeatable deployment files were added, including Procfile, runtime.txt, requirements-prod.txt, render.yaml, and a Vercel-compatible folder. A GitHub Actions workflow runs the pytest suite and syntax checks on push and pull requests, with a disabled deployment job until platform secrets are configured. Local production-mode verification succeeded: the health endpoint returned HTTP 200 with database status ok and debug mode off. The full test suite passed with 59 tests. Backup and recovery guidance covers the SQLite database and uploads directory. Known limitations include ephemeral storage on free hosting and the need for managed databases and object storage for real production persistence. No live deployment was claimed because it requires account access and explicit user approval.
